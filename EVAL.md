# EVAL.md — how Playbook Redliner is measured (the contract behind the Improvement Changelog)

Judges must be able to run `pnpm eval` from a clean clone and reproduce every number in
`IMPROVEMENT_CHANGELOG.md` at **zero API cost** (replay), then `pnpm eval --live` to re-run for real.
Everything below is implemented in `src/eval/**` and driven by `scripts/eval.ts` / `scripts/report.ts`.

## 2. Gold format (`gold.json`)

```json
{
  "contractId": "cuad-corio-hosting",
  "items": [
    { "id": "g01", "ruleId": "LOL-CAP", "paragraphIds": ["p0087", "p0088"], "status": "deviation",
      "cuadCategory": "Cap On Liability", "spanText": "…", "labeler": "cuad+human",
      "note": "Cap is 3 months' fees, protects Vendor only", "expectedFix": "mutual cap at 12 months' fees + carve-outs" },
    { "id": "g02", "ruleId": "INSURANCE", "paragraphIds": [], "status": "missing", "labeler": "human" },
    { "id": "g03", "ruleId": "MFN", "paragraphIds": ["p0041"], "status": "compliant", "cuadCategory": "Most Favored Nation",
      "labeler": "cuad+human", "note": "MFN benefits Customer" }
  ]
}
```
`status ∈ deviation | missing | compliant`. Compliant items exist so that over-flagging is penalised.

## 3. Matching

A finding **matches** a gold item when `ruleId` is equal and either the paragraph sets intersect, or both are
`missing` for that rule. Each gold item matches at most one finding (highest confidence wins).

- **TP**: gold `deviation|missing` matched by a finding with status `deviation|missing`.
- **FP**: a finding with status `deviation|missing` that matches no gold `deviation|missing` item (includes flagging a gold `compliant` clause).
- **FN**: gold `deviation|missing` with no matching finding of status `deviation|missing`.
- `needs_review` findings count as neither TP nor FP for F1 but are reported separately ("escalations").

## 4. Metrics (per contract, then macro-average; micro also reported)

| Metric | Definition | Kind |
|---|---|---|
| **Issue-detection F1** (primary) | P/R/F1 from §3 | deterministic |
| Deviation accuracy | over gold items located by any finding, share with correct status | deterministic |
| **Redline validity** | over TP findings with a proposal: `applies` (every op passes `validateOp`) ∧ `checks` (all `rule.checks` pass on the rendered clause) ∧ `judge.satisfies_rule` | deterministic + independent judge |
| Minimality | judge.minimal ∧ changed-character ratio ≤ 0.6 for `replace` ops | mixed |
| Document integrity | apply all TP proposals → `validateDocx`: ok, `collateralParagraphIds = []`, change count = ops, LibreOffice headless opens it (when available; recorded as attempted/ok) | deterministic |
| Citation hallucination rate | references to "Section X"/"§ X" in rationale, comments, memo whose X is not a section in the document ÷ all such references | deterministic |
| Cost / latency / tokens | from `RunStats` | deterministic |
| Human review load | edits + rejects ÷ findings in the recorded review sessions (`trajectories/human/*.json`) | observational |

**Independent judge**: OpenAI `gpt-5.6-sol` (`reasoning.effort: "high"`), structured JSON, prompt = rule position +
original clause + rendered redlined clause + comment; outputs `{ satisfies_rule, minimal, preserves_intent,
drafting_quality (1–5), reason }`. Never the model under test. Cached like every other call.

## 5. Configs and fairness

All configs run on the same 12 contracts with the same playbook and the same `ourParty`. Baselines use the
same Claude model as the pipeline. `b0-chat` gets no playbook (it represents "paste into a chat assistant");
`b1-prompt` (the official baseline) gets the playbook in one prompt. Differences in resources are stated in the
report (calls, tokens, cost).

## 6. Replay cache (reproducibility)

`src/agent/llm.ts` hashes every request (`model + system + messages + tools + output_config`) to
`evals/cache/<config>/<contractId>/<sha256>.json`. Modes: `live` (call, no write), `record` (call + write),
`replay` (read; missing entry → hard error unless `--allow-live`). `pnpm eval` defaults to `replay`;
`pnpm eval --live` = `record`. Judge calls are cached under `evals/cache/judge/`. Runs are deterministic
in replay, so `evals/results/*.json` are byte-reproducible.

## 7. Outputs

- `evals/results/<config>.json` — per-contract metrics, aggregate, run stats, per-finding judgements.
- `evals/results/summary.md` — the comparison table (`pnpm report`), pasted into `IMPROVEMENT_CHANGELOG.md`.
- `evals/results/changelog-data.json` — consumed by the `/evals` page.
- `evals/runs/<config>/<contractId>/` — findings + trajectory for inspection (committed for `b1-prompt` and `final`).

## 8. Commands

```
pnpm fetch-cuad                       # downloads CUAD_v1 (GitHub data.zip) to data/raw/cuad
pnpm build-dataset                    # builds data/contracts/cuad-* from the shortlist (+ gold drafts)
pnpm synth --seed 11 --count 3 && pnpm synth --hardcase
pnpm eval --config b1-prompt          # replay by default; add --live to re-run
pnpm eval --all                       # every config
pnpm report                           # summary.md + changelog-data.json
```
